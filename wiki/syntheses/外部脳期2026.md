# 外部脳期2026: 公開 Cosense 期の終焉予感

## 結論

**外部脳の需要は減っていない**。しかし「**外部脳が Scrapbox/Cosense で公開されている**」という 2017〜2024 の形式は、2026 に入って **終焉の signal が出始めた**。具体的には:

1. cosense-cli による複数プロジェクト（**private を含む**）の集約という新ワークフローが現れた
2. その集約結果を入れるコンテナこそが「外部脳」と呼ばれるべきもの
3. private を含む以上、「外部脳」は **public にできない** ([[../concepts/書く場所による言語化の効果.md|書く場所による言語化の効果]] 2026 Update の「private ⊃ public」原則の帰結)
4. 並行して LLM Wiki パターン（Karpathy）が公開 external_brain_in_markdown を **うろ覚えクエリ** に対して抜群に機能させ、外部脳の役割が「ストック」から別物へシフトしている

これは [[../../raw/external_brain_in_markdown/pages/外部脳期.md|外部脳期]] (2024-09-04 開始) の **内部での質的移行**であって、外部脳期そのものの終焉ではない。Scrapbox期→外部脳期と同じ系列の「公開Cosense期 → ???期」への移行予感。

## 期の構造（時系列）

| 期 | 期間 | 媒体 | 形式 |
|---|---|---|---|
| はてなダイアリー期 | 2007-10 〜 2018-03 | はてな (public) | 単独ブログ記事 |
| Scrapbox期 | 2017-04 〜 2024-09 | Scrapbox (public) | リンクされたページ群 |
| 外部脳期（GitHub期） | 2024-09-04 〜 | GitHub `external_brain_in_markdown` (public) | Cosense はビュー、データが本体 |
| **? 期（予感）** | 2026〜 | cosense-cli 集約 (private 含む) + LLM Wiki | コンテナが private、view が AI 経由 |

→ 各移行点で本人は **「本質的に X は変化していない」** と articulate している（[[../../raw/external_brain_in_markdown/pages/西尾泰和のScrapbox→西尾泰和の外部脳.md|西尾泰和のScrapbox→西尾泰和の外部脳]] 2024-09-04: 「X を指す[[ポインター]]/[[ハンドル]]として使う名前が外的要因で変わるのは好ましくない」）。**変化するのはビュー、本質は外部脳というプロセス**。

## 6 つの seed（2026-06-04 user articulation）

### seed 1: 公開状況の終焉予感

> 外部脳の需要は減っていないが「外部脳が Scrapbox/Cosense で公開されている状況」は終焉するかもしれない

→ 「需要」と「公開形式」を分離。**需要は constant、形式は変動**。形式の終焉は媒体の特性（Cosense の public/private 並置）と新ワークフロー（cosense-cli 集約）の相互作用で発生する。

### seed 2: 果樹園のたとえ（2026-06-04 本人 articulate、独立 concept 化）

> 果樹園が広いのでドローンを導入したら収穫が上がった
> 果樹園を持たない人がドローンを導入しても同様の収穫向上はない

→ Cosense/Scrapbox 上の知識ネットワーク = 果樹園、AI Agent = ドローン。**ドローンの収穫向上は果樹園の存在に依存**する。同じ AI を、果樹園を持たない人が使っても同等の収穫増はない。

含意:

1. **AI の価値は蓄積に依存する** — AI と蓄積は対等な input ではなく、AI 効果は蓄積を前提条件として乗算的に効く。「AI さえあれば誰でも同じ知的生産性」への反例
2. **後発 ingest でも物理ネットワークは作れるが「自分の延長」感は再現できない可能性** — 本人発話「『自分の思考の履歴』『自分の延長と感じることができるかどうか』の点で差がある。この差に意味があるかどうかは知らない」
3. **[[../concepts/巨人の肩直通エレベーター.md|巨人の肩直通エレベーター]]との対比** — ヘリコプター（公共知識へ access、民主化する）vs ドローン（個人果樹園での収穫、民主化しない）。AI には 2 種類の価値があり、本人自己紹介 Story は両方を区別して語れる

詳細は独立 concept page → [[../concepts/果樹園のたとえ.md|果樹園のたとえ]]

### seed 3: 外部脳 ≠ 文章のストック

> 人間が自ら書いた文章のストックは外部脳か？
> そもそも脳は文章のストックではない / それは本棚の役割

→ 2024-09-04 の articulate「**脳とは単なるデータの集まりではない / プログラムとデータの組み合わせ**」（[[../../raw/external_brain_in_markdown/pages/西尾泰和のScrapbox→西尾泰和の外部脳.md|当該ページ]]）の延長。2026 update としてさらに「**ストックは本棚の役割**であり、外部脳の本質ではない」と境界を引き直している。

含意:
- 「外部脳」と「本棚（書籍ストック）」は別カテゴリ
- 外部脳 = データ × プログラム × 相互作用 × 出力
- 「公開された Markdown ストック」は外部脳のうち **ビュー / アーカイブ層**であって、本体ではない

### seed 4: 創作目的による Wiki の活性化（qualia-san-wiki 事例）

> 単なる情報の集積ではなく「新しい創作を作る」という目的が設定されたことで Wiki が活発に変化し始めた気がする
> 死んだテキストを置く倉庫にしない

→ shokai 2017「[[../../raw/external_brain_in_markdown/pages/別途下書きなどしない.md|死んだテキストを置いておく倉庫にしない]]」の **AI 時代版・目的駆動版**。情報の集積だけでは Wiki は死ぬ。**創作目的**が活性化の駆動力。

[[../concepts/書く場所による言語化の効果.md|書く場所による言語化の効果]] の「賑わう private」と同型: 賑わいの源は **「もう一つの知性」との相互作用** + **目的の設定**。創作目的は AI に対する具体的依頼となり、AI が「死んだ倉庫」を「果樹園」に変える触媒になる。

### seed 5: cosense-cli + 外部脳コンテナ問題

> cosense-cli
> ・複数のプロジェクトに散ってるものを集約できる
> ・private も含めるとする
> ・ではその結果が入るべきコンテナは何か
>   ・それが「外部脳」なのではないか
>   ・private が public を包み込んでいる
>   ・その「外部脳」は public にできないのではないか

→ 「外部脳」というコンテナの**正体**が articulate された:

- 個別の Cosense プロジェクト ≠ 外部脳
- 複数プロジェクトを集約したもの = 外部脳
- 集約には private が含まれる
- ⇒ 外部脳の本体は **必然的に private**

これは [[../concepts/書く場所による言語化の効果.md|書く場所による言語化の効果]] 2026 Update の **private ⊃ public** 原則の具体的応用。`external_brain_in_markdown` (public GitHub) は外部脳の **public projection** に過ぎず、本体ではない。

含意: 2024-09-04 で「Cosense はビュー、データ（GitHub）が本体」と articulate されたが、2026 にさらに「**GitHub に出ているのもまた projection、真の本体は private 集約コンテナ**」と再articulate される。**2 段階の本体退避**が起きている。

### seed 6: うろ覚えクエリへの LLM Wiki の効果

> 公開されている external_brain_in_markdown をベースにして作成した Karpathy の LLM Wiki は「こんな話をしなかったっけ」といううろ覚えクエリーに対して抜群の成果を出す
> 具体例: 箱を積まないで地面からジャンプ
> 「Scrapbox は忘れたことを思い出させてくれる」のさらに先
>   リンクサジェストは明示的な検索アクションなしに気づかせてくれる
>   明示的に「あれなんだっけ」と思ってる場合の支援は、現状の Cosense の検索と 2hop link より LLM Wiki の方が効果的

→ **本Wiki（`llm-wiki-about-nishio`）自身が事例**である。「箱を積まないで地面からジャンプ」は 2026-06-04 同日のセッションで本人が想起→本Wikiで [[../concepts/猿と箱のたとえ.md|猿と箱のたとえ]] に到達した実例（[[../../log.md|log.md]] 該当エントリ参照）。

| 機能 | Scrapbox 検索 + 2hop link | LLM Wiki |
|---|---|---|
| ❶ 受動的気づき（書いてる最中にサジェスト） | 強い | 同等またはやや弱い |
| ❷ 明示的「あれなんだっけ」(active recall) | 弱い（厳密一致依存） | **強い**（意味的 + 概念的 + 比喩理解） |

→ Scrapbox の「忘れたことを思い出させてくれる」は ❶ 中心。LLM Wiki は **❷ を加える**ことで外部脳の active recall を本人レベルに引き上げる。

これは外部脳の役割 redefinition: **「ストック」から「うろ覚え再生器」へ**。public Markdown を直接 grep する時代は終わり、LLM 経由のクエリ・統合・連想が標準になる。

## 統合: 何が起きているか

3 つの方向が同時に動いている:

1. **コンテナの private 化**（seed 5）: 外部脳の本体が public Cosense → public GitHub → private 集約 と退避
2. **役割の変化**（seed 3, 6）: ストック（本棚）→ 動的生成器・うろ覚え再生器（果樹園?）
3. **活性化の駆動力**（seed 4）: 集積目的では死ぬ → 創作目的 + AI 相互作用で活きる

これらすべてが指している先は: **「ビュー = public ストック / 本体 = private 動的システム」という二層構造**。Karpathy LLM Wiki パターンは public ビューにも価値があることを示したが、本人の運用上の本体は private に退避していく。

[[../concepts/書く場所による言語化の効果.md|書く場所による言語化の効果]] 2026 Update が言う「private ⊃ public」が、外部脳というスケールでも成立する。

## このWikiへの含意

本Wiki (`llm-wiki-about-nishio`) は **public external_brain_in_markdown** に Karpathy LLM Wiki パターンを適用したもの。つまり本 synthesis が描く「公開 Cosense 期の終焉予感」の構造の中では、本Wikiは **public ビュー側**に属する:

- 本体退避が進めば、本Wikiが扱えるのは「外部脳の public projection 部分」のみ
- ただし seed 6 が示すように、**public projection だけでもうろ覚えクエリには抜群に効く**
- 本Wikiの第一目的（[[../meta/目的-自己紹介ページ更新.md|自己紹介ページ更新]]）は public-facing なので、public ビュー側に留まるのは整合的
- 本体（private 集約コンテナ）側で別の Wiki が並走する設計が必然 — [[../../../llm-wiki/wikis.yaml|wiki森]] における role 分担と整合
