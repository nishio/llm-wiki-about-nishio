# 第一目的: 自己紹介ページを更新する

## なぜこれが第一目的か

このWikiは本人が 2026-05-27 に**そもそも「自己紹介ページ更新の前段」として構想した**もの（[[../../raw/external_brain_in_markdown/pages/日記2026-05-27.md|日記2026-05-27]]）:

> デライトについてのLLM Wikiを作ったのと同じように、nishioについてのLLM Wikiを作れば良いのでは、というアイデア
> 生身の僕は年スケール、10年スケールの視点を見落としがち
>
> 放置していた **TODO:自己紹介ページを更新する** に関しても、そのLLM Wikiが作れば良いのでは
>   ConnectingDotsシステムの「Dotはどのような粒度であるべきか」も事前に決めるのではなくLLM Wikiにまとめてからやればよいのでは
>   **意思決定のハンドルを握ったまま意思決定しないことによって停滞しているプロジェクトに対して、ハンドルを手放してAIに委ねることによって前進させる**

→ つまりこのWikiは **[[../concepts/曖昧な停滞.md|曖昧な停滞]] している自己紹介更新を解消するための AI 委任実装**。
→ ingest を蓄積するだけで派生成果物に接続しないと、本Wiki自身が新たな「曖昧な停滞」になる。本ページはそれを防ぐための明示目標。

## 自己紹介ページの定義

| 媒体 | URL | 状態 |
|---|---|---|
| 公式英語/日本語 | http://nhiro.org/ja.html | **メンテされていない**（本人が認めている、アカデミア時代の経歴のまま） |
| GitHub Pages プレビュー | https://nishio.github.io/entrypoint/ | 2026-01-24 に作成、保全用 |
| GitHub リポジトリ | https://github.com/nishio/entrypoint | 2026-01-24 作成 |
| Scrapbox | [[../../raw/external_brain_in_markdown/pages/自己紹介.md|自己紹介.md]] | 最新だが**歴史が長く検索で nhiro.org の方がヒットする** |
| Amazon 著者セントラル | 更新済（2024頃） | 既に Plurality 言及あり |

問題:
- 「世界が興味を持つゾーン」（2024年都知事選 / Plurality / ブロードリスニング）に入っているのに、英語圏向けの自己紹介が古い
- 検索流入は古い nhiro.org に流れる
- Scrapbox 自己紹介ページは積み重ね型で「最新版どれ」が一見してわからない

## 本人の指針（2026-02-05 AI星占いより本人が抽出）

更新作業を進める上で、本人が腹落ちした方針:

1. **完成版を作らない** — 「半年後に必ず違和感が出る」（A案/B案で悩むのではなく、今完成させない）
2. **何者かより何を考えているか** — bio の表面より思考の現在地
3. **過去の自分を消さない** — 「ブロードリスニングの実践者」だけに軸足を置かない（複数アイデンティティの並走）
4. **2026年夏以降「名乗れる言葉」が固まる** — 今は探索・下書き・公開思考の時期
5. 自己紹介は **「名刺」ではなく「作業ログの入口」**

→ 本Wikiが「作業ログの入口」の役割を担う。

## 構造的ひらめき: Dots / Stories / Views 3層

2026-02-11 のひらめき「[[../concepts/自己紹介と歴史は共通の構造を持つ.md|自己紹介と歴史は共通の構造を持つ]]」より、自己紹介ページは次の 3層構造で生成される:

- **Dots (点)**: 検証可能な最小単位の事実カード（日付・誰が・何を・URL）
- **Stories (線)**: Dot を選んで並べたキュレーション（複数のナラティブが並行可能）
- **Views (面)**: 同じ Dot/Story を表示する UI（タイムライン / プロジェクト別 / 人物別）

「自己紹介」は Stories の一つ（Profile Story）、固定プロフィールは Story の表紙（短い bio）に退く。

→ このWikiの[[../concepts/ConnectingDots.md|ConnectingDots]] と整合的。本Wikiでの ingest が **Dot の蓄積場** として機能できる。

## 補助原型: [[../concepts/自己紹介ポーカー.md|自己紹介ポーカー]]

実績の並べ方論。**強そうな実績をただ並べてもノーペア**、「役」（実績間の関連の見出し方）を作れて初めて強くなる:
- ペア: 同じ数字（属性）の実績
- フラッシュ: 同じスート（領域）
- ストレート: 同じ流れ
- スリーカード: 解釈の言葉で3つを繋ぐ（例: エンジニア × 起業家 × SF作家 = 「未来を作る仕事」）

→ Dot を並べるだけでは弱い。Story を作る時に**役を見出す解釈言語**が必要。
→ 本Wiki が概念ページ群で蓄積している「軸」（[[../topics/知的生産.md|知的生産]] / [[../topics/Plurality.md|Plurality]] / [[../topics/ブロードリスニング.md|ブロードリスニング]] / [[../concepts/シリアルマスタリー.md|シリアルマスタリー]] / [[../concepts/AI協働の4パターン.md|AI協働の4パターン]] 等）は、**役を作るための解釈言語の候補**。

## 場と目的設定の留意（[[../../raw/external_brain_in_markdown/pages/自己紹介とポーカーの役.md|本人発言]]より）

> 場によって何が強いカードであるかが異なる

- 英語圏 IT/AI コミュニティ: 都知事選ブロードリスニング、Plurality 邦訳プロジェクト、Cybozu Labs 主幹研究員
- アカデミア: 博士(理学)、技術経営修士、TokyoTech 特定准教授（2024年3月退任済）、論文・著書
- 一般ビジネス: 著書のロングセラー、サイボウズ × 民主主義案件
- マダミス会: 「強そうだと認識されると不利」→ あえて弱めの自己紹介

→ **単一の自己紹介ページは難しい**。本人発言「複数の Story が並行する前提」と整合する。
