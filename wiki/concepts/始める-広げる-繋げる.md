# 始める / 広げる / 繋げる

## フレームの定義

2023-03-05、villagepump の inajob による「水が布に染み込むようにその染みを広げる」メタファーへの応答として、nishio が **3つの独立した能力** に分解したフレーム。

| 軸 | 能力 |
|---|---|
| **A: 始める** | 何もないところに新しいことを始める |
| **B: 広げる** | 一つのテーマにエネルギーを注ぎ込んで広げていく |
| **C: 繋げる** | 二つのものにつながりを見出す |

出典: [[../../raw/external_brain_in_markdown/pages/始める-広げる-繋げる.md|始める-広げる-繋げる.md]]（villagepump からの本人クリップ）。

## nishio 自身の自己評価: C > A > B

> 僕はBが少し低い=飽きっぽい
> Cは特に意識してないがAは意識して増やしてる
> なのでC>A>Bなのだろう

- **B（広げる）が低い** ← 自認する **飽きっぽさ**
- **A（始める）は意識的に増やしている** ← 訓練対象として明示
- **C（繋げる）は無意識で発揮されている** ← 暗黙の強み

## 三者三様（対話の構造）

同じ対話で3人が自己診断し、見事に分かれた:

| 人 | 順位 |
|---|---|
| nishio | C > A > B |
| inajob | B > … （Aが苦手、Cは無意識） |
| sta | A > B > C |

→ 単一の「正しい型」ではなく、**3軸プロファイルが個人差を可視化する道具** として機能している。
nishio 本人のコメントも「三者三様で面白い」で締めくくられている。

## B（広げる）が低いことの戦略的補償

B が低い nishio が C 中心で生きるための戦略が、外部脳の他のページから読み取れる:

### 1. A を意識的に増やす = 「雑に始める」

- [[../../raw/external_brain_in_markdown/pages/雑に始める.md|雑に始める]]: 「0を1にできなくても、まず0.1にしておく」「そしてその情報を共有する=シグナリング」
- [[../../raw/external_brain_in_markdown/pages/重要なプロジェクトほど雑に始める.md|重要なプロジェクトほど雑に始める]]: 「重要なプロジェクトほど見切り発車にネガティブなバイアスがかかる」ことへの対抗原則

→ A を増やすこと自体が方法論化されている。「広げる」を諦めて「始める」に振っている、と読める。

### 2. C を発動させるために A を量で稼ぐ

同じ対話で、nishio は inajob の「染み」メタファーと自分の認識のズレを次のように説明:

> 「点」が先にあり、後から「つながる」もの
> 「これが何か過去の点とつながるかなー？」と考えた時に、過去の点がたくさんある方がつながりを発見できる確率が上がる
> だからたくさん点を打って速やかに公開する
> 囲碁の「布石」とか、シューティングの「弾幕」とかと似たような雰囲気

→ **A（点を打つ）の量で C（繋げる）の発火確率を稼ぐ**、というメカニズム。
具体例として挙げられているのは: NovelAI 一コマ漫画 → LINEスタンプ → クオリアさん爆誕 → ChatGPT寄稿依頼でクオリアさんの話を書く（[[../../raw/external_brain_in_markdown/pages/Keichobot.md|Keichobot]] とのconnect！） という連鎖。**事前計画ではなく事後的に発見される繋がり**。

→ [[ConnectingDots.md|ConnectingDots]] の方法論的基盤として、この A→C 連鎖が位置付けられる。

## B（広げる）への懐疑: 「やれることを広げる病」

B が低いことは弱点として描かれているわけではない。むしろ B の有害性に関する考察が別ページにある:

[[../../raw/external_brain_in_markdown/pages/やれることを広げることがやりたいことになる.md|やれることを広げることがやりたいことになる]]（2017-12-01 Facebook）:

> 自分の「やれること」を広げることが「やりたいこと」になってしまうことがある。
> 利用と探索のトレードオフにおいて、探索に資源を振ってしまう。
> ランダムに目の前に現れた課題を解決することを続けていると、年を取った時に「だいたい何でもできるけど何にも特化していない人」になってしまう。

→ B を**過剰に発揮する人への警告**。「広げる」が無自覚に駆動される can/will の病として批判されている。
→ nishio の C>A>B プロファイルは、**この病を回避する** 自己設計とも読める。

[[../../raw/external_brain_in_markdown/pages/すでにあるものを広げるのか新しいものをつくるのか.md|すでにあるものを広げるのか新しいものをつくるのか]] も同じ A vs B の選択を扱っており、「[[../../raw/external_brain_in_markdown/pages/不確実性.md|不確実性]] が低い B にバイアスがかかる」ことを指摘している。

## C（繋げる）の二面性

[[../../raw/external_brain_in_markdown/pages/繋げるか繋げないか.md|繋げるか繋げないか]] では C にも逆向きの力が議論されている:

> AとBを繋げたら、お互いメリットがあって win-win で良いのでは！
> 不用意に繋げると調整コストがかさむから可能な限り疎結合を保った方が良い

→ C は単純な強みではなく、「繋げる/繋げない」の判断を伴うジレンマ。
→ nishio の C は **個人内での「点と点を繋げる」**（自己の中に布石として撒いた Dot を後から繋ぐ）であって、**外部の物事を強制的に統合する**ことではない、と読める。

## inajob メタファーとの対比

同じ対話で、inajob の「水が布に染み込むように染みを広げる」メタファーと nishio の「布石/弾幕」メタファーが対比される。

| | inajob | nishio |
|---|---|---|
| イメージ | 連続的な染みの拡張 | 飛び地に点を打って事後に繋ぐ |
| 主な能力 | B（広げる） | A→C |
| 動因 | 心地よい状態の維持 | Connecting The Dots（事後発見） |
| 飛び地 | 観測できない（隣接していないから） | 撒いた直後は飛び地、後から繋がる |

inajob 自身のコメント:
- 「(nishio)さんは染みが広がるのが早いような気がする」「広がる より 広げる という感じ」
- 「あと、飛び地で染みがあるように見える」

→ 外部から観測した nishio 像と、本人の方法論（A の量で C を発火させる）が整合する。

## Open Questions

- 「飽きっぽい」と nishio が認める B 低下は本当に弱みか、それとも C>A>B プロファイルにとっての必要条件か（B が高いと A の量が出せない）
- C（繋げる）の発火を意図的に増やす方法はあるか。それともランダム性に委ねるしかないか
- inajob の「染みを広げる」と nishio の「布石」は、知的生産戦略として混ぜられるか / 個性として住み分けるべきか
- B を意識的に増やすべきフェーズはあるか（例えばプロダクト/書籍の完成局面）

## Updates

### 2026-06-04: リンコグラフィーの move 用語との接合

本人が会話中に 3軸 と [[発散ムーブと収束ムーブ.md|発散ムーブ／収束ムーブ]] を明示的に接続:

| 3軸 | move 種別 |
|---|---|
| **繋げる (C)** | 収束ムーブ（critical backlink move = 複数のバックリンクを持つ move） |
| **始める (A)** | 飛躍のある発散 |
| **広げる (B)** | 飛躍のない発散 |

- A と B の差は **飛躍の有無**（inajob「染み」vs nishio「飛地」の対比を一般化）
- A → C の順序が move 用語で再述される: 「飛地を作る A が無いと、それを束ねる収束ムーブ C は構成不可能」
- 本人評価「**収束ムーブは複数視点に支えられた判断だから成功確率が高い、収穫のイメージ**」が、自己評価 C 最強の理論的裏付けとなる

詳細: [[発散ムーブと収束ムーブ.md|発散ムーブと収束ムーブ]]
