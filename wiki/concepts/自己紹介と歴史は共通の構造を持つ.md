# 自己紹介と歴史は共通の構造を持つ

## 中核の主張

2026-02-11、本人が長期停滞していた [[../meta/目的-自己紹介ページ更新.md|TODO:自己紹介ページを更新する]] と並行して [[../../raw/external_brain_in_markdown/pages/g0vの歴史を整理したい.md|g0vの歴史を整理したい]] を考えていた際の **結晶化**:

> [[../../raw/external_brain_in_markdown/pages/自己紹介と歴史は共通の構造を持つ.md|自己紹介]] と [[../../raw/external_brain_in_markdown/pages/歴史.md|歴史]] は **共通の構造** を持つ

→ どちらも「**事実の集積 → 主観的キュレーション → 表示**」の同じ構造で生成される。
→ 同じシステムで個人プロフィールと公共史を扱える。

## 3層構造（GPT5 との対話で結晶化）

| 層 | 内容 | 例 |
|---|---|---|
| **Dots（点）** | 検証可能な最小単位の事実 | 「2024-05-06 都知事選で安野候補陣営にブロードリスニング協力」「2018 エンジニアの知的生産術出版」 |
| **Stories（線）** | Dot を並べてコメント(語り)を添える「作品」 | Profile Story / Resume Story / Plurality 邦訳プロジェクト史 / dd2030 プロジェクトの歴史 |
| **Views（面）** | 同じ Dot / Story を表示する UI | タイムライン / 人物別 / プロジェクト別 / 言語別 |

ポイント:
- **Story は何本でも増える前提**で設計する（単一の正史を作らない）
- View は「薄く作れる」（SayItの参考例: PDF議事録を検索・共有しやすいUIにする = ビューの発明で価値）
- 同じ Dot を複数の Story が引用できる、逆引きも自動生成可能

## 「自己紹介」は Profile Story として解ける

> 「自己紹介ページ」は "プロフィール" ではなく **「ストーリーの1つ」** として解ける
> 自己紹介 = Stories のうちの一つ（Profile Story / Resume Story）
> "固定プロフィール" は、せいぜい Story の表紙（短い bio）に退く
> その人の活動履歴（Dots）から、どれを見せるかは人間が編集する

— GPT5 との対話（本人「これも同感」）

→ 自己紹介ページは独立した実体ではなく、**Dot 倉庫の上に乗る複数の View の一つ**。
→ 言語別・文脈別に複数のナラティブを並走させる設計。

## 個人と公共を同じシステムで扱える

本人発言:

> 単一の正史を作るわけじゃないんで僕が好き勝手に歴史を描いていいでしょ、その歴史を構成する個々の事実が検証可能なものであればよく、僕の描いたナラティブが不満な人は別のナラティブを書いたらいい

→ **私性と公性の対立を解消**する設計:
- Dot: 公共的（検証可能、再利用可能、CC0/GitHub）
- Story: 主観的・私的（誰が編んでも良い、複数並走）
- View: 用途依存（薄く、何個でも作れる）

→ Plurality 本自体がこの型の参考例（git ベース、CC0、forkして自分版を作るのを奨励）。

## 本人が否定したアイデア（重要な負の指針）

GPT5 が提案した中で本人が明示的に否定:

1. **「言語別テンプレ」**: 「これはアホの発想だと思う」
   - 多言語は「テンプレ」ではなく「**別編集の並立**」
   - 言語は文脈の一要因にすぎない、必要なのは「同じ Dots から、別の Stories を作れる」こと

2. **「ジレンマ」と整理されたもの**: 「これはジレンマではなくないか？」
   - 「薄さ」と「堅実さ」: 薄さ = サービスの責務を小さくする、堅実さ = データの最小単位を長期運用できる形にする。両立する

3. **「収集の自動化」**: 微細な点を全部"確定データ"にするとノイズ爆発
   - 3段階: 「拾ってきた候補(未確定) → Inbox」「Inbox から Dots に昇格させる編集」「Dots から Story を作る」

## つくる順番（最小実装）

GPT5 提案、本人同意:

1. **Dot のスキーマを決める（薄く）**: date / refs / entities / verifiability だけで始める
2. **Story のスキーマを決める（自由度高く）**: dot_id 配列＋言語別 caption / note
3. **View を 1 個だけ作る**: まずは「Story ページ」だけ（カードを順に表示・引用元リンク）
4. **逆引き（dot → 含まれる stories）を自動生成**

→ 静的 HTML 出力可能であるべき（本人要件）。
